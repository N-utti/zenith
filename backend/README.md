# backend — 제니스 API 서버

FastAPI · SQLAlchemy 2(async) · Alembic · PostgreSQL 16 + pgvector · Anthropic SDK.
계약은 [04 · API 명세서](https://app.notion.com/p/3aaa4716604681a6bba4e0367463e8eb), 스키마는 [03 · ERD·DB 설계서](https://app.notion.com/p/3aaa471660468142a4a1cbf2e44466b3) — **이 코드가 그 기계 판독본이다.** 정본은 Notion([docs/README.md](../docs/README.md)).

## 빠른 시작

```sh
cp .env.example .env                                   # 로컬은 COOKIE_SECURE=false 로 둔다
python -c "import secrets; print(secrets.token_urlsafe(48))"   # → .env 의 JWT_SECRET (필수 · 기본값 없음)
docker compose -f ../infra/docker-compose.yml up -d db  # 포트가 겹치면 ZENITH_DB_PORT=5435 + DATABASE_URL 수정
uv sync
uv run alembic upgrade head
uv run python scripts/seed.py                          # 워크스페이스·게시판 3·채널 2·개발팀·데모 계정 3
uv run uvicorn app.main:app --reload --port 8000       # → http://localhost:8000/api/docs
```

데모 계정은 프론트 목과 같다 — `sujin@zenith.co.kr`(사원) · `donghyun@`(팀장) · `jaeho@`(임원), 비밀번호 `zenith1234`.

```sh
uv run pytest            # Postgres 가 있으면 zenith_test DB 를 만들어 실DB 테스트까지, 없으면 그것만 건너뛴다
uv run ruff check .
```

OpenAPI 밖 — 아래 "설계와 어긋나는 것" 11 |

프론트(`frontend/`)도 같은 규약으로 옮겼다 — 토큰을 갖지 않고, `csrf` 쿠키만 읽어 헤더로 되돌리며, access 만료 시 refresh 후 1회 재시도한다. refresh 는 같은 오리진 탭들이 `navigator.locks` 로 줄을 서서 회전 토큰이 겹치지 않고, 어떤 요청이든 진짜 401 을 받으면 프로필을 비워 로그인 화면으로 간다(`frontend/README.md` "인증은 쿠키다").

access **쿠키**의 수명은 refresh 와 같다(14일). 15분은 토큰의 `exp` 가 판정한다 — 쿠키를 15분에 버리면 브라우저가 만료 신호(`AUTH_EXPIRED`) 대신 "쿠키 없음"만 보내 프론트가 재발급을 시도할 수 없다.

스텁을 구현할 때는 `register_stubs` 의 행을 지우고 라우터에 함수를 쓴 뒤 `openapi.json` 을 다시 뽑는다.

## 계약의 강제

산문 명세는 아무것도 강제하지 못한다(docs/README). 여기서는 두 가지로 강제한다.

1. **`openapi.json` 을 커밋한다.** 라우트를 바꾸면 `uv run python scripts/export_openapi.py`. `tests/test_contract.py::test_openapi_json_is_current` 가 어긋남을 잡는다.
2. **`CONTRACT_PATHS`** (tests/test_contract.py) — 04·13 의 경로 목록. 서버에서 사라지면 테스트가 깨진다. 폐기된 경로(`/attendance/approvals*`, `check-in`)가 되살아나도 깨진다.

다음 단계는 프론트가 `openapi.json` 에서 타입을 생성하는 것(frontend 몫).

12. **§5 채팅 멤버십 모델(2026-09-08) — 04·03 은 초대·탈퇴를 정하지 않았다. Notion 04 v1.3 §5 반영 완료(2026-09-08).** 공개 채널은 만들 때 활성 사용자 전원을 `channel_members` 에 넣고, admin 이 계정을 만들면(`admin.create_user`)·시드가 돌면 모든 공개 채널에 넣는다 — 15명 사내라 초대·탈퇴 API 없음(필요해지면 `POST /channels/{id}/members`). DM 은 `is_dm=true`·`name=""` 인 두 사람짜리 채널, 같은 두 사람의 DM 은 하나(두 사람 다 멤버인 DM 을 찾는다). 응답 모양: `GET /channels` = `{items:[{id, name, is_dm, members:[{id,name}], unread, last_message|null}]}`, `POST /channels` 201 은 `unread 0`·`last_message null`(재사용된 DM 도 — 목록은 GET 으로), `GET /channels/{id}/messages` = `{items[](오래된 순), next_cursor}` 커서는 `/admin/audit` 과 같은 `(created_at, id)` base64(`app/paging.py`). 비활성 계정도 멤버다(새 공개 채널에도 들어간다 — 복직하면 보여야 하고, 메시지 이력도 보존) — 목록·소켓에서 걸러내지 않는다. 공개 채널 이름은 부분 unique 인덱스(`uq_channels_public_name`, alembic 7b3e9c2d1f05)로 경합까지 막고, DM 짝은 트랜잭션 자문 잠금으로 하나만 생긴다. 감사 기록량은 소켓(소켓당 (채널, op) 한 번)과 REST(요청마다)가 다르다 — 판정은 같다. **비공개 채널(2026-10-02, 이슈 #221 — Notion 04 §5·03 반영 예정).** `channels.is_private`(03 에 없는 칸, alembic `6b2d8e4f1a73`). (a) `POST /channels {name, is_private:true, member_ids:[…]}` → 201, 멤버는 만든 사람 + `member_ids`(빈 배열이면 혼자). 두 칸은 **같이** 와야 한다 — 한쪽만·`is_private` 가 참·거짓이 아님(`StrictBool`, `"true"` 도 거절)·DM 에 끼움·없는/비활성 사용자는 422. 이렇게 엄격한 이유: 전에는 모르는 칸을 버려서 비공개를 청한 사람에게 **전원이 들어오는 공개 채널**을 만들어 줬다(조용한 공개 금지). (b) 이름 중복 409 는 **공개끼리만** — 비공개와 같은 이름의 공개 채널은 그냥 생긴다(409 를 주면 안 보이는 채널의 존재가 샌다). `uq_channels_public_name` 의 조건도 `NOT is_dm AND NOT is_private` 로 좁혔다. (c) `ChannelOut.is_private`(DM 은 false) — 프론트는 목록에 이 칸이 있어야 「비공개로 만들기」를 그린다. 홈 `unread[].is_private` 도 같이. (d) 멤버 변경은 비공개 채널만(공개·DM 은 422): `POST /channels/{id}/members {user_ids}` → 200 `ChannelOut`(이미 멤버는 건너뜀, 없는/비활성 422), `DELETE /channels/{id}/members/{user_id}` → 204(자기 자신이면 나가기, 멤버 아닌 사람 404). 요청한 사람이 멤버가 아니면(없는 채널 포함) 403 + `acl.denied`. **멤버면 누구나** 바꾼다(채널에 만든 사람 칸이 없다 — 만든 사람만으로 좁히려면 03 에 `created_by` 가 먼저). 권한 확인과 반영은 채널별 트랜잭션 자문 잠금 안에서 — 확인과 반영 사이에 요청한 사람이 빠지면 늦은 요청이 그 사람을 되살리는 경합(릴레이에서 재현)을 막는다. 변경은 감사 `channels.members_changed {added|removed}`(생성 시점 명단도 `{created:true, added}` 로). (4) 감사 `docs.comment_edited`(detail `comment_id`·`before` 120자 — 이전 본문은 행에 안 남는다). 삭제(24)와 공통 앞부분을 `_own_comment` 로 모았다. 알고 둔 한계: 바뀐 미리보기는 DB 만 바뀐다 — 열려 있는 알림함은 새로고침 전까지 옛 글(24·27 과 같음). 삭제·고치기 거부 403 문구는 「내 댓글만 고치거나 지울 수 있습니다」 하나다(감사는 `method` 로 가른다). 프론트가 할 일: `gen:api` 뒤 손으로 붙인 `DocComment.edited_at` 걷기 — **생성 타입에서 `edited_at` 이 required 라 목(`docsDb.ts`)의 시드 댓글 4개와 `addComment` 에 `edited_at: null` 을 넣어야 `tsc` 가 통과한다**, 목의 「그대로면 안 고친 것」 비교는 서버처럼 앞뒤 공백을 다듬은 뒤에, `COMMENT_EDIT_ENABLED` 걷기.
