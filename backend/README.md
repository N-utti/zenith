# backend — 제니스 API 서버

FastAPI · SQLAlchemy 2(async) · Alembic · PostgreSQL 16 + pgvector · Anthropic SDK.
계약은 [04 · API 명세서](https://app.notion.com/p/3aaa4716604681a6bba4e0367463e8eb), 스키마는 [03 · ERD·DB 설계서](https://app.notion.com/p/3aaa471660468142a4a1cbf2e44466b3) — **이 코드가 그 기계 판독본이다.** 정본은 Notion([docs/README.md](../docs/README.md)).

## 빠른 시작

```sh
cp .env.example .env                                   # 로컬은 COOKIE_SECURE=false 로 둔다
python -c "import secrets; print(secrets.token_urlsafe(48))"   # → .env 의 JWT_SECRET (필수 · 기본값 없음)
docker compose -f ../infra/docker-compose.yml up -d db  # 포트가 겹치면 ZENITH_DB_PORT=5435 + DATABASE_URL 수정
uv sync
uv run alembic upgrade head
uv run python scripts/seed.py                          # 워크스페이스·게시판 3·채널 2·개발팀·데모 계정 3
uv run uvicorn app.main:app --reload --port 8000       # → http://localhost:8000/api/docs
```

데모 계정은 프론트 목과 같다 — `sujin@zenith.co.kr`(사원) · `donghyun@`(팀장) · `jaeho@`(임원), 비밀번호 `zenith1234`.

```sh
uv run pytest            # Postgres 가 있으면 zenith_test DB 를 만들어 실DB 테스트까지, 없으면 그것만 건너뛴다
uv run ruff check .
```

## 구조

```

└─ routers/         auth · me · docs · channels · boards · search · ai · attendance · approvals · admin
alembic/            비동기 env.py · versions/
scripts/            export_openapi.py · seed.py · reindex.py(벡터 백필) · recache_text.py(평문 백필, #391)
```

프론트(`frontend/`)도 같은 규약으로 옮겼다 — 토큰을 갖지 않고, `csrf` 쿠키만 읽어 헤더로 되돌리며, access 만료 시 refresh 후 1회 재시도한다. refresh 는 같은 오리진 탭들이 `navigator.locks` 로 줄을 서서 회전 토큰이 겹치지 않고, 어떤 요청이든 진짜 401 을 받으면 프로필을 비워 로그인 화면으로 간다(`frontend/README.md` "인증은 쿠키다").

access **쿠키**의 수명은 refresh 와 같다(14일). 15분은 토큰의 `exp` 가 판정한다 — 쿠키를 15분에 버리면 브라우저가 만료 신호(`AUTH_EXPIRED`) 대신 "쿠키 없음"만 보내 프론트가 재발급을 시도할 수 없다.

스텁을 구현할 때는 `register_stubs` 의 행을 지우고 라우터에 함수를 쓴 뒤 `openapi.json` 을 다시 뽑는다.

기존 행은 정규화하지 않는다(파일럿 전, 15명). **DM 숨기기**: 본문 없음 → 204, DM 만(채널 422), 멤버 아님 403. **`channel_members.hidden_at`**(03 에 없는 칸, alembic `9d4e2f6a1c58`) 에 시각을 적고 `GET /channels` 와 홈 `unread[]` 가 `IS NULL` 로 거른다 — 멤버십은 그대로라 방·과거 메시지·검색·자료실·첨부 내려받기는 전과 같다(이슈 「숨긴 DM 의 안읽음·검색·알림」: 홈 배지만 같이 숨기고 나머지는 안 건드린다 — 치운 건 목록의 줄이지 대화가 아니다). 숨긴 직후 본인에게 `channels` 이벤트. **풀리는 때**: (a) 그 방에 새 메시지가 오면 누구 글이든 — `realtime/chat.py` 가 메시지 INSERT 와 같은 트랜잭션에서 그 채널의 `hidden_at` 을 전부 NULL 로(받는 쪽은 목록에 없는 채널의 `msg` 를 받으면 목록을 다시 받으므로 별도 이벤트 없음), (b) 숨긴 사람이 `POST /channels {dm_user_id}` 로 같은 상대와 다시 열면(이미 있는 DM 을 돌려주는 그 길에서 내 행만). 정한 것: 공개 채널 이름은 전원이 바꿀 수 있다(임원만으로 좁히려면 `rename_channel` 한 줄). 공개·비공개 채널 숨기기는 없다(채널은 나가기(12)가 있고, 공개 채널은 전원 멤버라 숨기면 「전원이 본다」는 전제가 흐려진다). 숨김 해제 경로는 따로 없다(위 두 경우로 충분 — (b) 로 풀리면 본인에게 `channels` 이벤트). 숨기기는 감사에 안 남긴다(본인 목록의 일). 알고 둔 한계: 상대가 비활성이면 (b) 가 422 라 (a) 뿐이다(대화 기록은 검색·자료실로 닿는다). 숨기기와 새 글이 정확히 겹치면 새 글이 있는데도 숨겨진 채 다음 글까지 남는다(`hide_channel` 의 ponytail 주석). 이름을 바꿔도 지난 멘션 알림의 `channel_name` 은 보낸 시점 이름 그대로다(누르면 `channel_id` 로 가니 동작엔 지장 없음). 프론트가 할 일: `gen:api` 뒤 `CHANNEL_MENU_ENABLED` 걷기.
27. **채팅 메시지 고치기·지우기 — 소켓 op `edit`·`del`, 이벤트 `msg_edit`·`msg_del`(2026-10-02, 이슈 #264 — 04 §4.1 에 없는 op, Notion 04 §4.1 반영 완료 2026-10-06 — 04 v1.16·03 v1.3).** 프론트(#263, `MESSAGE_EDIT_ENABLED`)가 제안한 계약 그대로. REST 가 아니라 소켓 — 보내기가 소켓이라 화면의 메시지 캐시를 바꾸는 주체를 하나로 둔다. `{op:'edit', channel_id, message_id, body}` → 멤버 전원에게 `{ev:'msg_edit', channel_id, message:{…MessageOut}}`, `{op:'del', channel_id, message_id}` → `{ev:'msg_del', channel_id, message_id}` + 멤버마다 `unread` 재방송(안 읽은 글이 지워지면 숫자가 준다). 보낸 사람에게도 돌아온다(프론트는 낙관적 반영 없음). **`messages.edited_at`**(03 에 없는 칸, alembic `b7c3e9a2d4f1`) — `MessageOut`(소켓 `msg`·`GET /channels/{id}/messages`)에 `edited_at`(고친 적 없으면 null). 판정: 쓴 사람만 — 남의 것은 `error FORBIDDEN` + 감사 `acl.denied`(소켓당 (채널, op) 한 번, detail 에 `message_id`), 없는 메시지·다른 채널의 id 는 `error NOT_FOUND`, 멤버 아니면 전과 같이 `FORBIDDEN`. 고치기 본문 규칙은 보낼 때와 같다(다듬기·1만 자·첨부 없으면 빈 글 `VALIDATION`), 첨부는 안 바뀐다, 글이 그대로면 아무 이벤트도 없다. 정한 것(이슈 「백엔드가 정할 것」): (1) 임원 확대 없음, (2) 기한 없음, (3) 행을 지운다(자리표시 없음), (4) 지운 메시지의 **멘션 알림(`payload.message_id`)은 같이 지운다**(댓글 삭제 24 와 같은 이유), 검색 색인(`tsv`)은 행과 함께 사라지고 고치면 DB 가 다시 만든다, 문서 카드는 행과 함께, **첨부 오브젝트는 MinIO 에 남는다**(URL 을 아는 멤버는 내려받을 수 있다 — 미참조 오브젝트 정리 없음, 16(d) 와 같은 천장. 자료실은 `messages.attachments` 를 읽으므로 자연히 빠진다), (5) **고친 글의 새 `@이름` 에는 알림을 만들지 않는다**(멘션은 보낼 때 한 번 — 고칠 때마다 알림이 가면 같은 사람을 여러 번 부른다. 필요해지면 보낼 때와 같은 `mention_targets` 를 차집합으로), (6) 지워진 것이 마지막 메시지여도 `channels` 이벤트는 안 보낸다(프론트가 목록을 다시 받는 기존 처리 유지), (7) 성공 감사 `chat.message_deleted`(detail `message_id`·`preview` 120자·`attachments` URL 목록 — 행이 사라지므로 여기에만 남고, 남는 MinIO 오브젝트를 찾을 단서다)·`chat.message_edited`(detail `before` 120자 — 이전 본문은 행에 안 남는다. 전문이 필요해지면 `message_edits` 표). 고치면 그 메시지의 멘션 알림 `preview` 도 새 본문으로 바꾼다(가리려고 고친 글이 알림함에 남지 않게). **감사 열람자(exec)는 DM·비공개 채널의 지운·고친 본문 앞 120자를 본다** — 26 의 비공개 채널 이름과 같은 종류, 의도한 것. 거부 감사 억제 키는 소켓당 (채널, op) 하나라(멤버 아님과는 다른 키) 같은 채널에서 남의 글 여러 개를 건드려도 첫 `message_id` 만 남는다. 지운 메시지의 멘션 알림은 행만 사라진다 — 이미 받은 사람의 열린 화면에는 새로고침 전까지 남고 누르면 채널만 열린다(24 와 같음). 프론트가 할 일: `gen:api` 뒤 손으로 붙인 `ChatMessage.edited_at` 걷기, `MESSAGE_EDIT_ENABLED` 걷기.
28. **영구 삭제는 휴지통에 든 문서만(2026-10-02, 이슈 #278) — 04 §3 DELETE 에 없는 409 `NOT_TRASHED`(새 코드).** `DELETE /docs/{id}?hard=1` 이 `deleted_at` 을 보지 않아, 휴지통 화면이 확인 창을 띄운 사이 누가 되돌린 문서를 임원이 그대로 영구 삭제할 수 있었다(프론트의 「휴지통 비우기」 #277 이 차례로 지우며 틈이 넓어짐). 등급 판정(403) 다음에 `deleted_at IS NULL` 이면 409 `{code: NOT_TRASHED}` — 문서는 그대로. 영구 삭제와 되돌리기(`/untrash`)는 문서 행을 `SELECT … FOR UPDATE` 로 읽어, 판정과 `_purge` 사이에 되돌리기가 끼는 ms 단위 틈도 없다(늦은 쪽은 잠금을 기다렸다가 404 또는 409). 프론트가 할 일: `usePurgeDoc`·`useEmptyTrash` 는 409 를 실패로 세어 문구로 알리므로 수정 없음, 목(`handlers.ts`)의 `hard=1` 을 서버에 맞추기, `gen:api` 재생성(409 설명만 늘어 타입 변화 없음).

56. **AI 열람 도구 — 근태·휴가·결재·자료실을 질문자 권한 그대로(2026-10-15, 사용자 결정 「질문자 권한 그대로」, Notion 04 §8·ARCHITECTURE §6 미반영).** `app/ai/data_tools.py` 의 도구 다섯을 `_turns(with_data=이름 집합)` 으로 준다: `attendance {month, who: me|team|company}` — me 는 그달 집계·특이일·휴가 신청·그해 연차 잔여(`_days`·`_summary`·`_balance`·`list_leaves`, 「이번 달」은 KST `today()`), team 은 팀장(자기 팀 `teams.lead_id`)·임원, company 는 임원(`team_grid` 와 같은 조건, `_staff`), 사람마다 월 집계; `approvals {box, status}` — `list_approvals` 그대로(최근 20); `approval_detail {id}` — `_can_view` 뒤 `_out`(본문은 `ai_doc_max_chars`, `<결재 본문>` 태그); `archive {query}` — `list_archive`(받을 수 있는 것만, 50건); `read_file {url}` — 채널 첨부는 내려받기 판정(멤버 + 살아 있는 메시지에 실린 것)과 같고, 문서 파일(`/api/files/{id}`)은 **자료실 목록과 같은 범위**(기록부에 있고 살아 있는 문서에 붙은 것 — HTTP 보다 좁다)로 가져와 `extract` 로 평문(상한 10MB, `<파일>` 태그). 사람이 쓴 글(본문·의견·제목·파일명·메모)은 전부 `_body()`. 거부는 `acl.denied {path: ai.<도구>, via}` 감사. **보는 사람 기준**: `/ai/chat`(질문자만 봄)은 다섯 전부, 채팅 `/ai`(채널 전원이 봄)는 `CHANNEL_SAFE` = 자료실·파일 읽기만 — 팀 근태·결재가 채널에 올라가지 않게(보안·코드 리뷰 HIGH; 채팅에서도 근태·결재를 쓰려면 「본인 것만」 변형으로). 팩트체커·cite 에는 없음. 결과는 번호 없는 평문이라 근거 카드·각주가 없다(ponytail: 결재 카드·근태 링크는 프론트 요청이 오면). 결과 글자는 `read_document` 와 같은 답변당 예산(`ai_doc_max_chars`)을 깎는다. 상태 이벤트 「자료를 보는 중」. 호출 상한은 검색과 공유(라운드당 3·라운드 3). 계약·openapi 변동 없음.
